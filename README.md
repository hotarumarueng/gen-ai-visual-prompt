# gen-ai-visual-prompt

画像・動画・資料・LP を生成AIで作るときの指示文（プロンプト）を、デザイン・撮影・映像の「型」で組み立て、出てきた結果を完成チェックで見て、直す指示を1つずつ出す Claude Code スキル。

## 導入（Claude に頼む）

Claude Code に次のように頼むと、Claude がこの README の「Claude への導入手順」を読んで入れる。

```
https://github.com/hotarumarueng/gen-ai-visual-prompt の README を読んで、スキルを導入して
```

非公開リポジトリなので、Claude Code を動かす端末で `gh auth status` が通る（このリポジトリを読める GitHub アカウントでログインしている）ことが前提。

## Claude への導入手順

この節は、導入を頼まれた Claude が上から順に実行するための手順。各手順の終わりの条件を満たしてから次へ進む。

1. **入れ先をユーザーに聞く。** 次の2つから選んでもらう。推測で決めない。
   - 個人用（どのプロジェクトでも使う）：`~/.claude/skills/gen-ai-visual-prompt/`
   - プロジェクト用（そのリポジトリだけで使う）：`<プロジェクトのルート>/.claude/skills/gen-ai-visual-prompt/`
   - 終わりの条件：入れ先の絶対パスが1つに決まった。
2. **入れ先に既にあるかを確かめる。** あれば、中身を消す前にユーザーに上書きしてよいかを聞く。手元で書き足した変更が消えるため。
   - 終わりの条件：入れ先が空、またはユーザーが上書きを了承した。
3. **一時フォルダに取得する。** 入れ先とは別の空のフォルダに取得する。
   ```
   gh repo clone hotarumarueng/gen-ai-visual-prompt <一時フォルダ>
   ```
   - 終わりの条件：`<一時フォルダ>/SKILL.md` と `<一時フォルダ>/references/` の10ファイルがある。
4. **スキル本体だけを入れ先に写す。** 写すのは `SKILL.md` と `references/` だけ。`README.md`・`.gitignore`・`.git/` は写さない（スキルとして読み込まれる必要がないため）。
   - 入れ先が `.claude/` の配下で、書き込みが権限設定やポリシーで拒否されたら、迂回せずに止まり、拒否されたことと、ユーザーが手で写すためのコピー元とコピー先のパスを伝える。
   - 終わりの条件：入れ先に `SKILL.md` と `references/*.md`（10本）があり、取得したものとファイルごとに内容が同じ（ハッシュか `diff -r` で確かめる）。
5. **一時フォルダを消す。**
   - 終わりの条件：一時フォルダが残っていない。
6. **ユーザーに結果と試し方を伝える。**
   - 入れた場所と、写したファイルの数。
   - スキルは Claude Code の新しいセッションから読み込まれるので、新しいセッションを開いて試すこと。
   - 試す頼み方の例：「DMのバナーの指示文を作って」「この画像、余白が詰まってるのを直したい」。名前を出して「gen-ai-visual-prompt を使って」と頼んでもよい。
   - 終わりの条件：上の3点を伝えた。

更新は同じ手順をやり直す（手順2で上書きの了承を取る）。削除は入れ先のフォルダを消す。

## 手で入れる場合

```
gh repo clone hotarumarueng/gen-ai-visual-prompt
```

取得したフォルダから `SKILL.md` と `references/` を、`~/.claude/skills/gen-ai-visual-prompt/`（個人用）か `<プロジェクト>/.claude/skills/gen-ai-visual-prompt/`（プロジェクト用）に写す。Claude Code の新しいセッションから使える。

## 何をするか

- **道筋A 新しく指示文を作る**：目的の6項目（作るもの・見る人・載せる文言・生成AIの種類・縦横比か尺・枚数）を確かめ、分野と型を1つ選び、その型の「指定する要素」をすべて埋めた指示文を書く。完成チェックと、直す指示の候補を1つ添える。
- **道筋B 出てきた結果を直す**：結果を完成チェックで見て、外れた点を1つ選び、残す部分を先に書いて変える条件を1つだけ書いた指示を出す。直った結果も同じチェックで見直す。

用語は3つ。

| 用語 | 意味 |
|---|---|
| 型 | 余白・三分割構図・ドリーインのように、名前の付いた作り方のパターン。10分野×10個 |
| 指定する要素 | その型を使うとき、指示文に必ず入れる項目 |
| 完成チェック | 出てきた結果が狙いどおりかを見る観点 |

## 分野

| ファイル | 分野 | 使う生成AI |
|---|---|---|
| `references/design.md` | バナー・告知画像のデザイン | 画像生成 |
| `references/composition.md` | 写真風画像の構図 | 画像生成 |
| `references/slide-layout.md` | 資料1枚のレイアウト | 資料・図解・Web |
| `references/camera-work.md` | 動画のカメラワーク | 動画生成 |
| `references/lp-parts.md` | LP のパーツ | 資料・図解・Web |
| `references/diagram.md` | 図解の型 | 資料・図解・Web |
| `references/background.md` | 背景 | 画像生成 |
| `references/lens.md` | 写真のレンズと画角 | 画像生成 |
| `references/lighting.md` | 動画の光 | 動画生成 |
| `references/art-style.md` | イラストの画風 | 画像生成 |

`SKILL.md` は全分野に共通する手順だけを持ち、分野ごとの型は `references/` に分けている。Claude は必要な分野のファイルだけを読む。

## 確かめたこと

- 名前を出さない頼み方（作る依頼1本・直す依頼1本、どちらもデザイン分野）で、スキルが自動で呼ばれ、道筋A・B がそれぞれ使われた（2026-11-18）
- 未確認：デザイン以外の分野の頼み方での自動呼び出し。出てきた指示文を実際の生成AIに送った結果。この README の「Claude への導入手順」を Claude に読ませて導入する流れ
