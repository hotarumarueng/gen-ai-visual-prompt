# gen-ai-visual-prompt

画像・動画・資料・LP を生成AIで作るときの指示文（プロンプト）をデザイン・撮影・映像の「型」で組み立て、出てきた結果を完成チェックで見て、直す指示を1つずつ出す Claude Code スキル。

> **このリポジトリについて**
> 導入は、エンジニアではない人が Claude に頼むだけで終わることを目指して書いている。下の「Claude への導入手順」は、人ではなく Claude が読んで実行するための手順。Windows の会社 PC のように権限や書き込みに制限がある環境で実際に詰まった点と、その回り方を織り込んである。

## 導入（Claude に頼む）

Claude Code を開き、次の1文をそのまま送る。

```
https://github.com/hotarumarueng/gen-ai-visual-prompt の README を読んで、スキルを導入して
```

あとは Claude が質問しながら進める。聞かれるのは「どこに入れるか」くらいで、パスワードやトークンを聞かれることはない。

このリポジトリは非公開なので、読む権限のある GitHub アカウントで、その端末の git か gh にログインしていることが前提になる。

## Claude への導入手順

この節は導入を頼まれた Claude が上から順に実行する。各手順の「終わりの条件」を満たしてから次へ進む。

### 相手と話すときの決まり

相手はエンジニアではない前提で話す。

- 1回の返答で頼む作業は1つにする。押す場所・打つ文字・確かめる表示まで書く。専門用語には一言の説明を添える。
- 相手に打ってもらうコマンドは、**貼り先（どのアプリのどの画面か）をコードブロックの前に書く**。1行にまとめ、`$` を含めない（チャットで変数や数式に化けることがある）。複数行の処理が要るときは、スクリプトファイルを Claude が書き、相手には「そのファイルを実行する1行」だけを渡す。
- パスワード・トークン・鍵・個人情報は、チャットに打たせない。必要なら、相手のログイン手順（ブラウザでの認証など）に任せる。
- コマンドはできるだけ Claude が自分で実行する。相手に頼むのは、Claude からは実行できない（拒否される・相手のログインが要る）ときだけにする。

### 0. 環境を確かめる

1. OS と、Claude 自身がコマンドを実行するシェルを確かめる。Windows では、Claude の実行シェルが Git Bash でも、相手がコマンドを貼るのは PowerShell であることが多い。
2. `git --version` と `gh --version` を実行し、使える方を控える。どちらも無ければ、相手に「git が入っていないので、入れる必要がある」と伝えて止まる（インストールは組織のルールがあるので、相手か管理者に任せる）。
3. 終わりの条件：OS・Claude のシェル・相手が貼るシェル・使える取得コマンド（gh か git）が分かった。

### 1. 入れ先を相手に聞く

次の2つを平易な言葉で示して選んでもらう。推測で決めない。

- 自分用（どのフォルダで Claude を使っても効く）：`~/.claude/skills/gen-ai-visual-prompt/`
- このプロジェクト用（このフォルダで使うときだけ効く）：`<プロジェクトのルート>/.claude/skills/gen-ai-visual-prompt/`

終わりの条件：入れ先の絶対パスが1つに決まった。

### 2. 入れ先に既にあるかを確かめる

あれば、上書きしてよいかを相手に聞く。手元で書き足した変更が消えるため。

終わりの条件：入れ先が空、または相手が上書きを了承した。

### 3. 一時フォルダに取得する

入れ先とは別の、空の一時フォルダに取得する（Claude Code の作業用フォルダがあればそこ）。

- gh があれば：`gh repo clone hotarumarueng/gen-ai-visual-prompt <一時フォルダ>/repo`
- gh が無ければ：`git clone --depth 1 https://github.com/hotarumarueng/gen-ai-visual-prompt.git <一時フォルダ>/repo`
- 認証で失敗したら：相手に「このリポジトリを読める GitHub アカウントでのログインが要る」と伝え、持ち主に招待を頼むか、`gh auth login` をブラウザで済ませてもらう。トークンを貼らせない。

終わりの条件：`<一時フォルダ>/repo/SKILL.md` と `<一時フォルダ>/repo/references/` の10ファイルがある。

### 4. スキル本体だけを入れ先に写す

写すのは `SKILL.md` と `references/` だけ。`README.md`・`.gitignore`・`.git/` は写さない。写したあと、ファイルごとにハッシュ（sha256）を比べる。

**書き込みが拒否されたとき**（組織のポリシーで `.claude/` 配下への書き込みが止められている環境がある）：

- 迂回しない。作業フォルダを `cd` でずらす、別のシェルや別のコマンドに言い換える、といった方法で通そうとしない。ポリシーを意図的に外すことになるため。
- 代わりに相手の手で写してもらう。Claude は書き込める場所（一時フォルダ）に、「コピーとハッシュ照合をまとめたスクリプト」を書き、相手には実行の1行だけを渡す。
  - Windows：PowerShell スクリプト（`.ps1`）にする。**ファイルの先頭に BOM を付けた UTF-8 で保存する**（Windows PowerShell 5.1 は BOM の無い UTF-8 を shift_jis として読み、日本語が化ける）。中では `&&` を使わない（5.1 では構文エラー）。日本語のファイルを読むなら `Get-Content -Encoding UTF8` を付ける。実行の1行は `powershell -NoProfile -ExecutionPolicy Bypass -File "<スクリプトの絶対パス>"`。
  - macOS・Linux：シェルスクリプトにし、`bash "<スクリプトの絶対パス>"` を渡す。
  - スクリプトは、ファイルごとに「一致／不一致」を表示し、最後に「すべて一致（N ファイル）」か「不一致あり」を表示する。
- 相手が実行したら、表示された結果を貼ってもらうか、Claude が入れ先を読んで（読み取りは許されていることが多い）11ファイルとハッシュを確かめる。

終わりの条件：入れ先に `SKILL.md` と `references/*.md`（10本）があり、取得したものとハッシュが全部一致した。

### 5. 一時フォルダを消す

取得したリポジトリと、手順4で書いたスクリプトを消す。

終わりの条件：一時フォルダに、この導入で作ったものが残っていない。

### 6. 相手に結果と試し方を伝える

- 入れた場所と、入ったファイルの数（11）。
- スキルは Claude Code の**新しいセッション**から読み込まれるので、いったん新しいセッションを開いてから試すこと。
- 試す頼み方の例：「DMのバナーの指示文を作って」「この画像、余白が詰まってるのを直したい」。うまく呼ばれないときは「gen-ai-visual-prompt を使って」と名前を出す。

終わりの条件：上の3点を相手が分かる言葉で伝えた。

更新は同じ手順をやり直す（手順2で上書きの了承を取る）。削除は入れ先のフォルダを消す。

## 手で入れる場合

```
git clone https://github.com/hotarumarueng/gen-ai-visual-prompt.git
```

取得したフォルダから `SKILL.md` と `references/` を `~/.claude/skills/gen-ai-visual-prompt/`（自分用）か `<プロジェクト>/.claude/skills/gen-ai-visual-prompt/`（プロジェクト用）に写す。Claude Code の新しいセッションから使える。

## 何をするか

- **道筋A 新しく指示文を作る**：目的の6項目（作るもの・見る人・載せる文言・生成AIの種類・縦横比か尺・枚数）を確かめ、分野と型を1つ選び、その型の「指定する要素」をすべて埋めた指示文を書く。完成チェックと、直す指示の候補を1つ添える。
- **道筋B 出てきた結果を直す**：結果を完成チェックで見て、外れた点を1つ選び、残す部分を先に書いて変える条件を1つだけ書いた指示を出す。直った結果も同じチェックで見直す。

用語は3つ。

| 用語 | 意味 |
|---|---|
| 型 | 余白・三分割構図・ドリーインのように、名前の付いた作り方のパターン。10分野×10個 |
| 指定する要素 | その型を使うとき、指示文に必ず入れる項目 |
| 完成チェック | 出てきた結果が狙いどおりかを見る観点 |

## 分野

| ファイル | 分野 | 使う生成AI |
|---|---|---|
| `references/design.md` | バナー・告知画像のデザイン | 画像生成 |
| `references/composition.md` | 写真風画像の構図 | 画像生成 |
| `references/slide-layout.md` | 資料1枚のレイアウト | 資料・図解・Web |
| `references/camera-work.md` | 動画のカメラワーク | 動画生成 |
| `references/lp-parts.md` | LP のパーツ | 資料・図解・Web |
| `references/diagram.md` | 図解の型 | 資料・図解・Web |
| `references/background.md` | 背景 | 画像生成 |
| `references/lens.md` | 写真のレンズと画角 | 画像生成 |
| `references/lighting.md` | 動画の光 | 動画生成 |
| `references/art-style.md` | イラストの画風 | 画像生成 |

`SKILL.md` は全分野に共通する手順だけを持ち、分野ごとの型は `references/` に分けている。Claude は必要な分野のファイルだけを読む。

## 確かめたこと

- 名前を出さない頼み方（作る依頼1本・直す依頼1本、どちらもデザイン分野）で、スキルが自動で呼ばれ、道筋A・B がそれぞれ使われた（2026-11-18）
- Claude にこの README を読ませて、空のプロジェクトへ導入できた。取得は git clone（HTTPS）、写したのは11ファイル、ハッシュは全部一致、一時フォルダも消えた（2026-11-18、入れ先は先に指定）
- 未確認：入れ先を聞く手順1と上書き確認の手順2のやりとり、書き込みが拒否されたときの手順4の流れ、デザイン以外の分野での自動呼び出し、出てきた指示文を実際の生成AIに送った結果
